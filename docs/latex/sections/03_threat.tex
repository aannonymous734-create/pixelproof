\section{Threat model and segment analysis}\label{sec:threat}
\rubric{threat model (15)}{We deliver a segment and trust-boundary analysis, six attacker profiles, a STRIDE mapping \cite{shostack}, and the AI component that enables the attack. Evidence: \cd{docs/THREAT_MODEL.md}.}

\subsection{Assets and trust boundaries}
\textbf{Assets.} (1) the pixel values; (2) the capture claim (product id, source, sensor, capture date, bands); (3) the processing history; (4) trust material: the source and processor private keys and the public-key registry; (5) the detector (model file and thresholds) and the audit log.

\textbf{Trust boundaries.}
\begin{itemize}
  \item \textbf{TB1 source:} the private key never leaves it.
  \item \textbf{TB2 transport:} anyone may read, modify, replay or drop messages (the attacker of our labs sits here).
  \item \textbf{TB3 ground processing:} only registered processors may add signed steps.
  \item \textbf{TB4 storage and API:} stored files may be swapped; the ground station re-verifies and logs.
\end{itemize}

\textbf{The AI component that facilitates the attack.} Generative inpainting and synthesis (diffusion, GANs, learned inpainting) let an attacker erase or invent content with plausible texture at almost no cost \cite{zhao}, and learned post-processing erases forensic traces. AI also powers our detector, as in recent work on satellite-image manipulation \cite{horvath}, but Section~\ref{sec:scenario} shows how much any learned detector degrades on manipulations it has never seen, which is the main reason provenance comes first.

\subsection{Operator access: an extra boundary}
The dashboard is itself an attack surface. An optional sign-in server gates access with JWT tokens \cite{rfc7519} stored in \texttt{HttpOnly} cookies, so that page scripts cannot read them (Section~\ref{sec:auth}). This protects the \emph{dashboard}; the ground-station ingest API has no authentication or TLS in the isolated lab, which is listed as a limitation (Section~\ref{sec:limits}).
