\section{The ground-station dashboard}\label{sec:dash}
\rubric{clarity (5) and architecture (15)}{We deliver an operator interface where every figure is read live from the API or the result files, with an optional sign-in server. Evidence: \cd{frontend/}, built into \cd{pixelproof/static/app}; \cd{backend/}.}

\subsection{Pages and data sources}
The dashboard is a React 18 + TypeScript application built with Vite into static files that the ground station serves itself, so the jury needs only Python. It works offline (fonts and 3-D scene bundled, no CDN), falls back to a 2-D diagram without WebGL, and enforces a strict Content-Security-Policy. A grouped sidebar (Monitor, Verify, Validate, Docs) becomes a slide-in menu on phones, and a 14-step guided tour opens each page and spotlights the real panel. Nothing on a page is typed by hand: counters come from the audit log, headline figures from the result files.

\subsection{Operator sign-in}\label{sec:auth}
A ground station shared by several operators needs an access screen. An optional sign-in server (Laravel 12, \texttt{backend/}) provides it; when the server is not running, the dashboard opens in an explicitly labelled \emph{open access} mode (the Overview and Analyse screenshots above were taken in that mode, so they contain no user name). The sign-in protects the \emph{dashboard}; the ground-station ingest API is unauthenticated in the isolated lab (Section~\ref{sec:limits}).

\begin{figure}[!htbp]
\centering
\includegraphics[width=0.86\textwidth]{signin.png}
\caption{The sign-in screen: e-mail and password only; access is restricted to authorised operators.}
\end{figure}

\begin{table}[!htbp]
\centering\small
\begin{tabularx}{\textwidth}{|L{3.6cm}|Y|}
\hline
\textbf{Property} & \textbf{How it is provided}\\
\hline
Tokens & two JWTs \cite{rfc7519} signed HS256: a short-lived \textbf{access token} (15 minutes) and a \textbf{refresh token} (7 days) carrying a \texttt{refresh} claim\\
\hline
Storage in the browser & \textbf{\texttt{HttpOnly}} cookies \texttt{access\_token} and \texttt{refresh\_token}, \texttt{SameSite=Lax}, path \texttt{/}; page scripts cannot read them (Figure~\ref{fig:cookies})\\
\hline
Request authentication & a middleware copies the access cookie into the \texttt{Authorization: Bearer} header on the server side, so no script handles the token\\
\hline
Refresh and rotation & the refresh token is also stored server-side; using it deletes it and issues a new pair, so a stolen refresh token works once\\
\hline
Logout & the stored refresh token is deleted, the access token is put on the blacklist, and both cookies are expired\\
\hline
Account rules & passwords stored as bcrypt hashes; login requires a verified e-mail address and an active account; login, registration and refresh are rate-limited to 10 requests per minute\\
\hline
\end{tabularx}
\caption{Properties of the operator sign-in, read from the backend code.}
\end{table}

\textbf{Known limits of this access layer.} The cookies are not flagged \texttt{Secure} in the current configuration (the lab serves plain HTTP on localhost); a deployment must serve both applications over TLS and set the flag. The sign-in server and the ground station are separate programs, so signing in does not authenticate calls made directly to the ground-station API.
